# 상식 퀴즈 게임 PRD

Oct 31, 2026 · @duckdeaths

## 개요

4개 카테고리 40문제를 4지선다로 풀고, 문제마다 정답 여부를 바로 확인하며, 최종 점수를 랭킹에 남기는 웹 기반 상식 퀴즈 게임이다.

**목표**

- 한 판을 10분 안팎으로 끝낼 수 있는 가벼운 퀴즈 경험 제공
- 문제마다 즉시 피드백(정답/오답 + 해설)으로 학습 효과 확보
- 점수와 순위 기록으로 재도전 동기 부여

**비목표 (이번 버전에서 하지 않는 것)**

- 실시간 다인원 대전, 채팅
- 회원가입·소셜 로그인 (닉네임만 입력)
- 사용자가 직접 문제를 등록하는 기능
- 유료 아이템, 광고

## 대상 사용자와 사용 시나리오

주 사용자는 짧은 시간에 상식을 점검하고 친구와 점수를 겨루고 싶은 10\~30대 일반 사용자다.

| 사용자 | 상황 | 원하는 것 |
| --- | --- | --- |
| 가벼운 플레이어 | 쉬는 시간에 혼자 한 판 | 빠른 시작, 바로 알 수 있는 정답 |
| 경쟁형 플레이어 | 친구·동기와 점수 비교 | 공정한 점수 규칙, 순위표 |
| 학습형 플레이어 | 약한 분야 보완 | 오답 해설, 카테고리별 정답률 |

## 게임 규칙

한 판은 4개 카테고리 각 10문제, 총 40문제를 순서대로 푸는 것으로 끝난다.

| 항목 | 규칙 |
| --- | --- |
| 문제 형식 | 4지선다 객관식, 정답은 1개 |
| 카테고리 | 한국사, 과학, 지리, 일반상식 |
| 문제 수 | 카테고리별 10문제, 총 40문제 |
| 출제 순서 | 카테고리 순서대로 진행, 카테고리 안에서 문제 순서와 보기 순서는 무작위 |
| 답 선택 | 보기를 누르면 바로 확정, 확정 후 변경 불가 |
| 피드백 | 확정 즉시 정답/오답 표시, 정답 보기 강조, 한두 줄 해설 표시 |
| 다음 문제 | 피드백 확인 후 "다음" 버튼으로 이동 |
| 종료 | 40번째 문제 피드백 후 결과 화면으로 이동 |
| 기록 | 닉네임과 함께 점수를 랭킹에 저장 |

문제당 제한 시간, 힌트, 중도 포기 시 기록 여부는 아래 '미결정 사항'에서 정한다.

## 사용자 플로우와 화면 구성

&#91;embedded content: 게임 진행 흐름 · 화면 4개, 분기 1개\]

화면은 시작, 퀴즈, 결과, 랭킹 4개이며, 퀴즈 화면 안에서 문제 표시 → 답 선택 → 피드백이 40번 반복된다. 결과 화면의 "다시 하기"는 시작 화면으로 돌아간다.

## 점수 산정과 순위 기록

정답 1개당 10점, 만점 400점이며, 동점이면 소요 시간이 짧은 사람이 높은 순위다.

**점수**

- 정답: +10점, 오답: 0점 (감점 없음)
- 총점 = 정답 수 × 10, 범위 0\~400점
- 제한 시간(F-09)을 넣을 경우 시간 초과는 오답 처리

**순위 정렬 기준 (위에서부터 우선)**

1. 총점 높은 순
2. 소요 시간 짧은 순 (첫 문제 표시부터 40번째 답 확정까지)
3. 기록 시각 이른 순

**기록 규칙**

- 40문제를 모두 푼 판만 랭킹에 저장한다.
- 같은 닉네임의 여러 기록을 모두 저장하되, 랭킹 목록에는 닉네임별 최고 기록만 보여 준다.
- 저장 항목: 닉네임, 총점, 정답 수, 카테고리별 정답 수, 소요 시간, 기록 시각
- 점수 계산은 서버에서 다시 검증해 클라이언트 조작을 막는다 (서버를 둘 경우).

## 데이터 모델

데이터는 문제(question), 플레이 기록(game\_record), 문제별 답안(answer\_log) 세 테이블로 충분하다.

**question**

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | INT, PK | 문제 번호 |
| category | ENUM('한국사','과학','지리','일반상식') | 카테고리 |
| content | TEXT | 문제 본문 |
| option\_1 \~ option\_4 | VARCHAR(200) | 보기 4개 |
| answer | TINYINT (1\~4) | 정답 보기 번호 |
| explanation | TEXT | 해설 (피드백에 표시) |
| difficulty | TINYINT (1\~3), NULL 허용 | 난이도, 이후 확장용 |

**game\_record**

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | INT, PK | 기록 번호 |
| nickname | VARCHAR(10) | 닉네임 |
| score | INT | 총점 (0\~400) |
| correct\_count | INT | 정답 수 (0\~40) |
| duration\_sec | INT | 소요 시간(초) |
| created\_at | DATETIME | 기록 시각 |

**answer\_log**

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| record\_id | INT, FK → game\_record.id | 어느 판의 답인지 |
| question\_id | INT, FK → question.id | 어떤 문제인지 |
| selected | TINYINT (1\~4, 시간 초과 시 NULL) | 선택한 보기 |
| is\_correct | BOOLEAN | 정답 여부 |

카테고리별 정답 수와 오답 다시 보기(F-14)는 answer\_log를 question과 조인해 계산한다. 서버 없이 만들 경우 같은 구조를 localStorage에 JSON으로 저장한다.

## 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 성능 | 답 확정 후 피드백 표시 0.2초 이내, 첫 화면 로딩 2초 이내 |
| 반응형 | 360px(모바일)\~1440px(데스크톱)에서 가로 스크롤 없이 표시, 보기 버튼 높이 44px 이상 |
| 접근성 | 정답/오답을 색만이 아니라 아이콘(✓/✗)과 텍스트로도 표시, 키보드 1\~4 키로 보기 선택 |
| 신뢰성 | 새로고침 시 진행 중인 판 복구 또는 처음부터 다시 시작 중 하나로 일관되게 처리 |
| 보안 | 정답 데이터를 문제 표시 단계에서 클라이언트에 노출하지 않기 (서버 채점 시) |
| 콘텐츠 | 모든 문제에 출처 확인된 정답과 해설, 출시 전 2인 이상 교차 검수 |

## 성공 지표, 마일스톤, 미결정 사항

**성공 지표**

- 완주율: 게임을 시작한 판 중 40문제를 끝낸 비율 70% 이상
- 재도전율: 결과 화면에서 "다시 하기"를 누른 비율 30% 이상
- 문제 품질: 정답률이 10% 미만이거나 95% 초과인 문제는 검토 대상으로 표시

**마일스톤**

1. 문제 40개와 해설 작성, 교차 검수
2. 시작·퀴즈·결과 화면과 즉시 피드백 구현 (P0)
3. 점수 저장과 랭킹 화면 구현 (P0)
4. 테스트 플레이 후 문제 난이도 조정
5. P1 기능 추가 (타이머, 오답 다시 보기, 문제 관리)

**미결정 사항**

- [ ] 문제당 제한 시간을 둘지, 둔다면 몇 초로 할지 (예: 15초)
- [ ] 빠르게 맞히면 보너스 점수를 줄지
- [ ] 랭킹을 서버 DB에 저장할지, 브라우저(localStorage)에만 저장할지
- [ ] 카테고리 하나만 골라 10문제만 푸는 모드를 둘지
- [ ] 중도 이탈한 판을 기록에 남길지
- [ ] 문제 은행을 40문제 고정으로 둘지, 카테고리별로 늘려 매 판 무작위 10문제를 뽑을지
