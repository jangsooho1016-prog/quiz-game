상식 퀴즈 게임 - 남은 구현사항 및 체크사항
작성일: 2026-11-02 (같은 날 두 번째 갱신)
기준 문서: docs/prd.md

요약: PRD 기능(F-01 ~ F-18)과 정해진 미결정 사항을 모두 구현했고, 첫 로딩·접근성·배치 기준도 맞췄다.
이번에 문제 사실 확인(3문제 수정), 제한 시간 없는 연습, 저장 실패 되돌리기, 파비콘, README,
Playwright 브라우저 점검, git 설정까지 끝냈다.
남은 것은 사람이 해야 하는 일(2인 교차 검수, 테스트 플레이, 실제 스크린 리더)과 서버 도입 여부뿐이다.

==============================================================

[P1] F-08 카테고리 전환 안내          [v] 새 카테고리 첫 문제 위에 이전 카테고리 결과와 함께 표시
[P1] F-09 문제당 제한 시간 15초       [v] 시간 초과는 오답, 정답과 해설 표시. 남은 5초부터 빨간색
[P1] F-14 틀린 문제 다시 보기         [v] 결과 화면 버튼 -> 문제, 내 답(또는 시간 초과), 정답, 해설
[P1] F-17 코드 수정 없이 문제 교체    [v] public/questions.json을 실행 중에 불러옴.
                                          배포된 dist/questions.json만 바꾸면 다시 빌드할 필요 없음.
                                          형식이 틀리면 시작 화면에 어느 항목이 틀렸는지 표시
[P2] F-16 카테고리별 최고 기록 탭     [v] 랭킹 화면 탭(전체/한국사/과학/지리/일반상식)
[P2] F-18 효과음, 정답 애니메이션     [v] 정답/오답 효과음(기본 켜짐, 끄면 기억), 정답 도장 애니메이션

구현하면서 정한 것 (확인 필요)
  - F-08: 별도 화면 없이 문제 위에 안내 띠로 보여 준다 (클릭이 늘지 않고 소요 시간에 영향 없음).
  - F-16: 카테고리 정답 수가 같으면 "판 전체" 소요 시간으로 비교한다.
          카테고리별 소요 시간은 따로 기록하지 않기 때문이다.
  - F-17: 문제 파일을 바꾸면 예전 판의 답안 기록은 옛 문제 id를 가리킨다.
          id를 재사용하지 말고 새 문제에는 새 id를 쓰는 것이 안전하다.

2. PRD '미결정 사항' - 결정 내용
==============================================================

(1) 랭킹을 서버에 둘지, 브라우저에만 둘지  -> [결정] 브라우저(localStorage) 유지 (11-02 다시 확인: 서버는 보류)
    * 기기마다 랭킹이 따로이고, 개발자 도구로 기록을 고칠 수 있다는 한계는 그대로다.
      친구와 같은 랭킹을 공유하려면 나중에 서버가 필요하다.

(2) 문제당 제한 시간                       -> [결정] 15초

(3) 빨리 맞힌 보너스 점수                  -> [결정·구현] 남은 3초마다 +1점, 최대 +5점
    * 정답 = 10점 + 보너스(0~2.9초 +5, 3~5.9초 +4, ..., 12~14.9초 +1). 오답·시간 초과 0점.
    * 문제당 최대 15점, 전체 도전 만점 600점 (PRD의 "정답 수 x 10, 최대 400점"에서 바뀜)
    * 저장할 때 답마다 걸린 시간으로 보너스까지 다시 계산해 검증한다.
    * 점수 규칙이 바뀌어 기존 기록은 새 저장 키(quiz-game/v2/...)로 새로 시작했다.
      예전 키의 데이터는 지우지 않고 그대로 두었다.

(4) 카테고리 하나만 푸는 모드              -> [결정·구현] "카테고리 연습" 10문제, 랭킹에 저장 안 함
    * 15초 제한과 보너스는 똑같이 적용. 결과·오답 다시 보기는 있고 순위는 없다.

(5) 중도 이탈한 판 기록                    -> [결정·구현] 랭킹에는 남기지 않고 통계에만 남김
    * 판을 시작하면 시작 기록이 남고, 끝내지 않으면 그대로 "중도 이탈"로 집계된다.

(6) 40문제 고정 / 문제 은행 확장           -> 아직 40문제 고정 (이번 범위 밖)
    * 출제 로직은 이미 카테고리당 10문제보다 많으면 무작위로 10개를 뽑는다.
      문제만 추가하면 된다.

구현하면서 임시로 정한 것 (확인 필요)
  - 새로고침: 진행 중인 판을 버리고 시작 화면으로 돌아간다 (통계에는 중도 이탈로 남음).
  - 순위: 닉네임의 최고 기록이 아닌 판은 "그 기록이 목록에 있었다면 몇 위인지"를 보여 준다.
  - 닉네임: 대소문자를 구분한다("ABC"와 "abc"는 다른 사람).
    로그인이 없어서 다른 사람이 같은 닉네임을 쓰면 같은 사람으로 취급된다.
  - 재도전율: 전체 도전을 끝낸 판만 분모로 센다 (연습 판의 "다시 하기"는 제외).
  - 문제 통계: 10번 이상 풀린 문제만 정답률로 판단한다 (적으면 "표본 부족").

             웹폰트는 문제·제목용 명조체만 쓰고 UI 글꼴은 시스템 한글 글꼴로 바꾸기
  [v] 360~1440px 가로 스크롤 없음 - 360px, 1280px(전 화면), 1440px(시작·퀴즈·랭킹) 확인
  [v] 보기 버튼 44px 이상 - 충족 (62px). 눌러야 하는 모든 버튼·선택지 44px 이상
  [v] 정답/오답을 ✓/✗와 글자로 표시, 키보드 1~4 선택 - 구현됨
  [v] 색 대비 - axe-core(WCAG 2.2 AA) 위반 0건: 라이트·다크 각 16개 화면 + 모바일 4개 화면.
      입력칸·보기·선택지 테두리 대비가 1.5~1.9:1이라 3:1 이상으로 고쳤다 (WCAG 1.4.11).
  [~] 스크린 리더 - 브라우저 접근성 트리로 버튼 이름, 눌림 상태, 알림 영역, 초점 이동을 확인했다.
      실제 스크린 리더(NVDA, VoiceOver)로 들어 보는 것은 아직 못 했다.
  [v] 제한 시간 접근성(WCAG 2.2.1) - 카테고리 연습에서 "제한 시간 없이 풀기"를 고를 수 있다.
      이때는 보너스가 없고(정답 10점) 랭킹에도 들어가지 않는다. 전체 도전은 15초 그대로다.
  [-] 정답이 클라이언트에 노출되지 않음 - 서버가 없어서 해당 없음 (정답은 문제 파일 안에 있음)

[성공 지표] (완주율 70%, 재도전율 30%, 정답률 10% 미만·95% 초과 문제 표시)
  [v] 통계 화면(랭킹 -> "통계 보기")에서 완주율, 재도전율, 문제별 정답률을 목표와 함께 보여 준다.

5. 추천 순서
==============================================================
